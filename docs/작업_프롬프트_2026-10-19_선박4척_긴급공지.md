# 🧾 작업 프롬프트 — 당일 작업 선박 4척 확장 & 긴급 플로팅 공지 (2026-10-19)

> 이 문서는 운영관리자(이춘학)의 요청을 **구현 가능한 프롬프트(작업 지시서)** 로 정리한 것입니다.
> 아래 1~6 항목을 순서대로 구현하고, 마지막에 회귀 테스트·빌드 검증까지 통과시킵니다.

## 0. 배경 / 한 줄 요약

> "당일 작업 선박이 **4척**이 될 수 있는 상황이 발생했다."

현재 앱은 **최대 2척(더블오더)** 기준으로 설계되어 있다.
선박 선택·임금 입력·선박별 자동계산·근무일지 저장·통계까지 **4척 기준으로 확장**하고,
추가로 **티커와 별개인 긴급 플로팅 공지** 기능을 신설한다.

## 1. 선박 선택 2척 → 4척 확장

**대상**: 임금계산기(`#wage-card`) · 근무일지(`#log-card`) 의 당일 입·출항 선박 선택

- 임금계산기 `⚓ 당일 입·출항 선박 선택` 목록에서 **최대 4척**까지 선택 가능
  (3번째·4번째 선택 시 차단 메시지 없이 정상 선택, 5척째부터 안내 후 차단)
- 근무일지 `🚢 입·출항 선박 달력 조회` 목록에서도 **최대 4척** 선택 가능
- 선택 칩의 순번 배지(`[1선박] · [2선박] · [3선박] · [4선박]`) 유지
- 안내 문구·placeholder 의 "2척" 표기를 모두 **4척** 기준으로 수정
  - `스케줄 선택(최대 2척) 또는 선박명 입력` → `최대 4척`
  - `작업 선박명 (2척 선택 시 더블오더)` → 4척 기준 문구
  - `선박을 최대 2척까지 선택하면 …` → `최대 4척까지 …`
- 복수 선박 명칭 규칙: 2척 = **더블오더**, 3척 = **트리플오더**, 4척 = **쿼드오더**
  (내부적으로는 "멀티오더"로 일반화, 사용자 문구는 척수에 맞춰 자동 표기)

## 2. 근무일지 임금 입력 블록 4개 (임금 1~4)

- 근무일지 입력 폼(`#dailyLogForm`)에 **임금 3 · 임금 4** 입력칸(`#logWage3`, `#logWage4`) 추가
- **평소에는 임금 1 · 임금 2 만 노출**
- **선박을 3척 또는 4척 선택했을 때만 임금 3 · 임금 4 블록이 나타남**
  - 판단 기준: `배 이름` 입력값의 선박 수(` / ` 구분) 또는 저장된 기록의 `wage3/wage4` 값 존재
  - 선박이 다시 2척 이하로 줄면 3·4 블록은 자동으로 숨김(값이 남아 있으면 유지 노출)
- 저장·삭제·초기화·달력 클릭(불러오기) 모두 임금 1~4 를 동일하게 처리
- 총액 = `wage1 + wage2 + wage3 + wage4`

## 3. 선박별 자동계산 블록 4개 (동일 규칙)

- `⏱️ 선박별 자동계산` 카드에 **3번 선박 · 4번 선박** 블록 추가
- **평소에는 1번·2번 블록만 보이고**, **선박 3척 또는 4척 선택 시 3·4번 블록이 나타남**
- **레이아웃 규칙 (중요)**
  - 노출된 블록들의 **세로 크기 합 = `⏳ 총 근무시간` 블록(정사각형)의 세로 크기**
  - 블록들은 **균등한 크기**로 분할 (2개 노출 시 1/2씩, 4개 노출 시 1/4씩)
  - 4개 노출 시에는 자동으로 컴팩트 모드(한 줄 배치·작은 글씨)로 전환해 글자가 잘리지 않게 함

## 5. 공지사항 자동 게시

- 위 변경 내용을 **공지사항(notices)** 에 자동 등록(`ensureTodayUpdateNotice`)
- 신규 문서 ID 사용 + `firestore.rules` 의 `isAutoNoticeId()` 에 동일 ID 추가(규칙 불일치 시 저장 거부됨)
- 우선공지(`isPriority: true`)로 최상단 고정
- 내용: 선박 4척 선택 / 임금 3·4 블록 / 선박별 자동계산 4블록 / 긴급 플로팅 공지 사용법

## 6. 긴급 플로팅 공지 (신규 · 티커와 별개)

> "긴급한 내용을 전달할 수 있게 티커와는 별개로, 내용을 적으면 **플로팅** 되어 접속한 사람들이 읽을 수 있게.
> **on/off** 기능과 **게시 기간** 설정. **관리자만** 작성 가능. 비번은 **9445**, 비번은 코드에도 보이지 않게."

- **표시**: 화면에 떠 있는(fixed) 긴급 공지 카드 — 상단 고정, 빨간 경고 스타일, 본문 자동 줄바꿈·링크 인식
  - 접속자는 `닫기`로 접을 수 있고, 접으면 작은 🚨 버튼으로 축소되어 언제든 다시 펼침
  - 새 공지(개정 번호 변경)가 올라오면 닫았던 사용자에게도 다시 노출
- **on/off**: `enabled` 스위치 — 끄면 즉시 모든 접속자 화면에서 사라짐(실시간 반영)
- **게시 기간**: 시작·종료 일시(datetime) 설정, 기간 밖이면 자동 숨김(1분 주기 재평가)
  - 빠른 설정 버튼: 1시간 / 3시간 / 오늘 자정 / 3일
- **관리자 전용 작성**
  - 비밀번호 **9445** 로 잠금 해제 (세션 유지)
  - **비밀번호 평문은 저장소/배포 번들 어디에도 두지 않는다**
    1순위: 서버 검증 `POST /api/emergency-unlock` (환경변수 `EMERGENCY_NOTICE_PIN`, 미설정 시 `SCREEN_LOCK_PIN` 사용)
    2순위: 빌드 시 주입되는 SHA-256 해시(`window.__EMERGENCY_PIN_SHA256__`)와 비교
  - 무차별 대입 방지(IP당 10분 10회) · 상수 시간 비교 적용
- **저장소**: Firestore `settings/emergency_notice`
  (`enabled`, `title`, `message`, `level`, `startAt`, `endAt`, `revision`, `updatedAt`)
  - `firestore.rules` 에 전용 검증(필드·길이 제한) 추가, 읽기는 전체 공개(인증 세션), 쓰기는 형식 검증 + 관리자

## ✅ 완료 기준 (Acceptance Criteria)

1. 임금계산기·근무일지에서 선박을 **4척까지** 선택할 수 있고, 5척째는 안내 후 차단된다.
2. 근무일지의 **임금 3·4 입력칸은 평소 숨김**, 선박 3~4척 선택 시 나타난다.
3. 선박별 자동계산 **3·4번 블록도 동일 규칙**으로 나타나며, 노출된 블록 높이의 합이 `총 근무시간` 정사각형 높이와 같고 균등 분할된다.
4. 계산 → 근무일지 전송 시 선박별 금액이 **임금 1~4** 에 각각 들어가고, 저장 총액이 4개 합계와 일치한다.
5. 통계·CSV·리포트·차트가 임금 3·4 를 포함해 집계한다.
6. 긴급 플로팅 공지는 **on/off·게시기간**이 동작하고, 관리자 PIN(9445) 없이는 작성창이 열리지 않으며, 소스 어디에도 평문 PIN 이 없다.
7. 변경 내용이 공지사항에 자동 게시된다.
8. `npm run check`(typecheck · validate · tokens:check · test) 와 `npm run build:obfuscate` 가 모두 통과한다.
