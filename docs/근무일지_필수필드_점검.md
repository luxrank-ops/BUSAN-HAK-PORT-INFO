# 근무일지(work_logs) 필수 필드 점검 — 11-16 FAIL 원인과 수정 (2026-11-18)

## 결론

2026-11-16 주간 자가 점검의 **`db.schema_drift` FAIL 1건("work_logs 표본 20건 중 20건 필수 필드 누락")은
데이터 문제가 아니라 점검 코드의 오탐**이었습니다. 실데이터(가입 근로자 73명·근무일지 1,731건)는
건드리지 않았고, 점검 기준을 앱이 실제로 쓰는 스키마에 맞췄습니다.

## 원인

당시 `server.ts` 의 `db.integrity` 프로브는 표본 문서마다 두 가지를 필수로 봤습니다.

```ts
const hasDate = Boolean(doc.date || doc.dateKey || doc.workDate || doc.createdAt);
const hasTerminal = Boolean(doc.terminal || doc.TERMINAL);   // ← 문제
```

`terminal`/`TERMINAL` 은 **터미널 선박 스케줄 문서**(`ships`, `vessel_schedules_cache`)의 필드입니다.
근무일지는 `public/js/app.js` 의 `saveWorkLog` 한 곳에서만 저장되고, 거기서 쓰는 필드는 다음과 같습니다.

```
date, workerId, shipName, wage1~4, coworkers, memo, totalPay, imageUrl, deletedAt, timestamp
```

`terminal` 은 처음부터 없습니다. 그래서 표본 20건이 전부 "누락"으로 계산돼 비율 100% → `FAIL` 판정이 났습니다.
(같은 점검이 `date` 누락을 잡은 것이 아니라, 전부 `terminal` 때문에 잡힌 것입니다.)

## 수정 (읽기 전용 · 원본 데이터 무수정)

1. 판정 로직을 `scripts/work-log-schema.mjs` 로 분리했습니다(순수 함수, 서버·테스트 공용).
   필수 키는 앱이 일지를 다시 꺼내는 데 반드시 필요한 **`date` 와 `workerId` 두 개**입니다.
   - 날짜: `date` → `dateKey` → `workDate` (옛 필드명 호환)
   - 작성자: `workerId`
   - 둘 다 없을 때만 문서 ID `workerId_YYYY-MM-DD` 의 접두사·접미사로 보완합니다
     (관리자 통계 집계가 쓰는 읽기 방식과 동일 → 옛 문서도 오탐이 되지 않음).
2. 보고서 문구에 **어떤 필드가 몇 건 비었는지**(`date 1·workerId 2`)와 문서 ID 보완 건수를 남깁니다.
   다음에 진짜 스키마 변화가 생기면 원인을 바로 알 수 있습니다.
3. 회귀 방지 테스트 `scripts/work-log-schema.test.mjs` — 앱이 저장한 모양 그대로의 문서 20건이
   누락 0건으로 PASS 하는지, 프로브가 다시 `terminal` 을 요구하지 않는지, 표본 점검이 원본을
   수정(`set/update/delete`)하지 않는지 검사합니다.
