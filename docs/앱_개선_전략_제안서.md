## 3. 개선 원칙 (모든 개선안의 공통 전제)

1. **디자인 불변**: 색·간격·타이포·라운드·그림자·모션 토큰을 변경하지 않는다. 새 시각 요소(새 배지·새 모달 스타일)를 만들지 않고, **기존 토스트·배지·문구 컴포넌트를 재사용**해 안내를 추가한다.
2. **한 번에 한 축**: 한 PR = 한 방향(A~E 중 1개). 정산 로직 변경과 화면 정리 변경을 섞지 않는다.
3. **측정 가능**: 모든 개선은 §7의 지표로 전후 비교한다. "좋아진 것 같다"는 판정 불가로 간주.
4. **회귀 방지 우선**: 새 기능 추가보다 **기존 기능이 조용히 깨지지 않게** 하는 작업을 먼저 한다.
5. **되돌리기 쉬운 단위**: 각 개선은 독립적으로 revert 가능하게(설정 플래그 또는 별도 PR) 진행한다.
6. **CI 통과가 완료 조건**: 모든 변경 후 `npm run check` 통과 + 관련 테스트 추가.

### 6-2. 무음 실패 제거 (B-1)

```js
// 공용 헬퍼 (기존 showToast 재사용 — 새 UI 요소/스타일 없음)
function reportFailure(scope, err, userMessage) {
  console.warn(`[${scope}] 실패:`, err);
  if (typeof showToast === "function") showToast(userMessage || `${scope} 정보를 갱신하지 못했습니다. 저장된 정보로 표시 중입니다.`);
```
