# 🧾 작업 프롬프트 — 꿍꿍따 끝말잇기 "댓글 릴레이" 개편 (2026-10-21)

> 운영관리자(이춘학) 요청을 구현 가능한 작업 지시서로 정리하고, 구현 결과까지 함께 기록한 문서입니다.

---

## 0. 배경 / 한 줄 요약

> "꿍꿍따 방식은 게임 대전 방식이 아니라, 사용자들이 시간 날 때마다 **댓글로 이어 가는 방식**으로 만들어줘.
> 대전 방식도 아니고 간단히 댓글로 이어가는 방식."

기존 `현장가이드` 탭의 꿍꿍따 카드는 **AI 대결 / 한 기기 2인 대전** 미니게임이었다.
턴 제한 시간(18초), 점수판, 힌트, 승패 결과 화면이 있어 "승부"를 전제로 했고,
기록도 **내 기기(localStorage)에만** 저장되어 동료와 공유되지 않았다.

이 개편으로 꿍꿍따는 **승부가 없는 비동기 댓글 릴레이**가 된다.
동료 누구나 쉬는 시간에 떠오를 때 **댓글 한 줄(세 글자 단어)** 을 남기고,
그 단어의 끝 글자가 다음 사람의 시작 글자가 되어 릴레이가 이어진다.

---

## 1. 요구사항 (Acceptance Criteria)

1. **대전 요소 완전 제거** — AI 대결·2인 모드 선택, 난이도, 턴 타이머(18초), 점수판, 승패 결과 화면, "한 판 더" 흐름을 모두 없앤다.
2. **댓글로 이어 쓰기** — 마지막 단어의 끝 글자로 시작하는 **세 글자 한글 단어**를 댓글로 남기면 릴레이가 이어진다.
3. **여러 사용자 공유** — 릴레이는 서버(Firestore)에 저장되어 **모든 동료에게 실시간**으로 보인다(내 기기에만 남지 않는다).
4. **언제든 참여·이탈** — 순서·차례·제한 시간이 없으므로 언제 참여해도, 중간에 나가도 된다.
5. **한 줄 메모(선택)** — 단어와 함께 짧은 응원·잡담 메모를 남길 수 있다(게시판과 동일한 금칙어·도배 필터 적용).
6. **막힘 해소** — 이어갈 단어가 떠오르지 않으면 내장 사전 기반 **추천 단어 칩**을 눌러 그대로 이어 쓸 수 있다.
7. **새 출발** — 릴레이가 막히거나 30개를 채우거나 12시간 멈추면 누구나 다음 릴레이를 열 수 있다(연속 갈아엎기 방지를 위해 60초 간격 제한).
8. **안전·비용** — 카드를 펼쳐 볼 때만 실시간 구독하고 접으면 해제한다. "휴식 시간에만 이용" 안내는 유지한다.
9. `npm run check`(typecheck · validate · tokens:check · test) 와 `npm run build:obfuscate` 가 모두 통과한다.

### Firestore 문서 형태

```
kkung_chain/active                  ← 현재 릴레이 상태 (문서 1개)
  round        : 3                  ← 릴레이 번호 (새 출발 시 +1)
  starterWord  : "부산항"            ← 이번 릴레이 출발 단어
  lastWord     : "이야기"            ← 마지막으로 이어진 단어
  wordCount    : 7                  ← 댓글로 이어진 단어 수
  usedWords    : ["부산항", …]       ← 중복 방지 목록 (최대 400개)
  lastNick     : "라싱반장"
  startedAt / updatedAt : serverTimestamp

kkung_chain/active/comments/{autoId}   ← 단어 댓글 (= 릴레이 한 수)
  round    : 3
  name     : "북항 포맨"
  word     : "이야기"
  prevWord : "부산항"
  memo     : "다음 분 힘내세요!" | null
  timestamp: serverTimestamp
```

### 보안 규칙 (`firestore.rules` — 섹션 10)

- `kkung_chain/active` : 로그인한 세션만 `get` (목록 조회 차단), 상태 갱신은 **두 가지 형태만** 허용
  - 이어쓰기 — `round`·`starterWord` 그대로 + `wordCount`·`usedWords` 정확히 1 증가
  - 새 출발 — `round + 1`, `wordCount = 0`, `usedWords = [출발단어]`, 직전 활동 후 **60초 경과**
  - 물리 삭제는 관리자 전용
- `kkung_chain/active/comments` : 세 글자 한글 단어 + 닉네임(1~50자) + 메모(≤120자) 형식만 생성 가능.
  **한 번 이어 쓴 단어는 릴레이 흐름 자체이므로 작성자도 수정·삭제할 수 없고 관리자만 정리**할 수 있다.
- 단어는 `^[가-힣]{3}$` 정규식으로 제한하므로 숫자·영문·긴 문장·URL 은 애초에 저장되지 않는다.

## 4. 검증

- `npm run check` — typecheck · validate · tokens:check · **test 190건 통과 / 실패 0**
- `npm run build:obfuscate` — 압축 산출물의 전역 API 검증 통과
- `npm run test:rules` — 로컬에 Java(JDK 21+)가 없어 건너뜀, GitHub Actions CI 에서 에뮬레이터로 실행

### 추가·교체된 회귀 테스트
- `scripts/kkung-relay-flow.test.mjs` (신규 12건) — 아주 작은 DOM·Firestore 스텁으로 **실제 화면 흐름**을 검증: 카드 열림→구독, 첫 릴레이 시작, 댓글로 이어쓰기(상태·피드·현황 동시 갱신), 사전 밖 단어 허용, 끝글자 위반/중복 차단, 금칙어 차단+관리자 알림, 다른 동료 댓글 실시간 반영, 진행 중 새 출발 차단/막힘 시 새 출발, 추천 칩 클릭 입력, 닉네임 저장·복원, 확인창 취소
- `scripts/kkung-relay.test.mjs` (신규 12건) — 사전 무결성, 끝말 잇기·중복 검증(사전 밖 단어 허용), 추천, 새 출발 조건(막힘/30개/12시간/진행 중 거부), 상태 문서 왕복, 상대 시각·참여 인원, **대전 잔재 금지(마크업·코드)**, 규칙↔화면 운영값 일치, 자산 버전 일치
- `scripts/rules/firestore-rules.emulator.test.mjs` (신규 10건) — 첫 릴레이 개설, 라운드·단어 수 조작 거부, 이어쓰기 +1, 새 출발 허용/60초 제한, 비로그인 읽기 차단, 단어 댓글 형식, 작성자 수정·삭제 불가
- `scripts/security-rules.test.mjs` (신규 1건) — 에뮬레이터 없이 도는 정적 안전망

### 배포 시 유의
- `firestore.rules` 변경이 포함되어 있으므로 **Firebase 배포(규칙 반영)** 가 함께 이루어져야 릴레이 쓰기가 동작합니다.
- 새 컬렉션 `kkung_chain` 에 필요한 **복합 인덱스는 없습니다**(`timestamp` 단일 필드 정렬만 사용).
